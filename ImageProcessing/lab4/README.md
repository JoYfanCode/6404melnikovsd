# Лабораторная работа №4

## Описание

Асинхронная загрузка и параллельная обработка изображений животных через API.

### Основные улучшения по сравнению с lab2:

1. **Асинхронная загрузка изображений** - использование `aiohttp` для одновременной загрузки нескольких изображений
2. **Асинхронное сохранение файлов** - использование `aiofiles` для неблокирующей записи файлов
3. **Параллельная обработка изображений** - использование `ProcessPoolExecutor` для обработки изображений на разных ядрах процессора
4. **Сохранение порядковых номеров** - номера изображений определяются в начале и не меняются в процессе обработки
5. **Детальное логирование** - вывод информации о каждом этапе обработки с указанием PID процесса

## Установка зависимостей

```bash
pip install aiohttp aiofiles
```

Или если используете pipenv:

```bash
pipenv install aiohttp aiofiles
```

## Использование

### Базовый запуск

```bash
python lab4/main_lab4.py
```

По умолчанию обрабатывается 5 изображений.

### Обработка определённого количества изображений

```bash
python lab4/main_lab4.py --limit 10
```

### Указание своей директории для сохранения

```bash
python lab4/main_lab4.py --output-dir my_images --limit 3
```

### Указание количества процессов для обработки

```bash
python lab4/main_lab4.py --limit 5 --max-workers 4
```

### Все параметры

```bash
python lab4/main_lab4.py --limit 5 --output-dir lab4_images --api-key YOUR_KEY --max-workers 4
```

## Параметры командной строки

- `--limit` - Количество изображений для обработки (по умолчанию: 5)
- `--api-type` - Тип API: `cat` (по умолчанию: `cat`)
- `--api-key` - API ключ (по умолчанию берётся из `.env` файла)
- `--output-dir` - Директория для сохранения результатов (по умолчанию: `lab4_images`)
- `--max-workers` - Максимальное количество процессов для обработки (по умолчанию: количество ядер CPU)

## Сравнение производительности

Для сравнения производительности синхронной (lab2) и асинхронной (lab4) версий используйте:

```bash
python lab4/compare_performance.py --limit 5
```

Этот скрипт запустит обе версии и выведет сравнительную статистику.

## Архитектура

### Асинхронный пайплайн обработки:

1. **Получение списка URL** - запрос к API для получения метаданных изображений
2. **Присвоение порядковых номеров** - каждому изображению присваивается номер, который не меняется
3. **Асинхронная загрузка** - параллельная загрузка всех изображений через `aiohttp`
4. **Асинхронное сохранение оригиналов** - сохранение исходных изображений через `aiofiles`
5. **Параллельная обработка** - применение свёртки в отдельных процессах через `ProcessPoolExecutor`
6. **Асинхронное сохранение результатов** - сохранение обработанных изображений через `aiofiles`

### Логирование

Программа выводит подробную информацию о каждом этапе:

- `Downloading image N started` - начало загрузки изображения N
- `Downloading image N finished` - завершение загрузки изображения N
- `Convolution for image N started (PID XXXX)` - начало обработки изображения N в процессе XXXX
- `Convolution for image N finished (PID XXXX)` - завершение обработки изображения N
- `Saving image N (type) started` - начало сохранения изображения N
- `Saving image N (type) finished` - завершение сохранения изображения N

## Дополнительное задание: Генераторный пайплайн

Реализован асинхронный генераторный пайплайн, где каждому этапу обработки соответствует отдельный генератор:

1. **fetch_metadata_generator** - получение метаданных из API
2. **download_generator** - асинхронная загрузка изображений
3. **process_generator** - параллельная обработка (свёртка)
4. **save_generator** - асинхронное сохранение результатов

Этапы работают параллельно и не блокируют друг друга благодаря использованию асинхронных генераторов.

### Запуск генераторного пайплайна

```bash
python lab4/main_lab4_pipeline.py --limit 5
```

Все параметры аналогичны основной версии.
